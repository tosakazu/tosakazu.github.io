SPSP — 理論編 2: 評価

SPSP は精度をデータで確認しながら設計している。本ページでは、その検証方法、 主要パラメータがなぜその値になっているか、既存ランキングとの精度比較、そして採用パラメータ一覧をまとめる。 各表とその解釈だけでページが閉じるよう書いてあるので、内部資料を別途読まなくても判断できる。

1. 精度評価の方法

1.1 テストセット

精度測定は 篝火#14 (2025-11-02) 〜 篝火#15 (2026-05-03) に開催された 参加者 100 名以上のガチ大会 を test に使う (§4 既存ランキング比較で N=37)。 パラメータ sweep など、より多くのサンプルが必要な節では 48 名以上に閾値を緩めることもあるが、 その場合は表のキャプションで明示している。

  • 期間: 6 ヶ月強の窓。古すぎる大会のメンバー構成は現在と乖離するため、最新シーズンに揃える。 区切りは国内で最も規模の大きい篝火 (#14 / #15) を両端に置いて固定。
  • 参加者下限: 小規模大会だとシード予想と結果の乖離が単なる運になりやすく、評価ノイズが増えるため (既存ランキング比較は 100 名以上、パラメータ sweep など大量サンプルが必要な検証は 48 名以上を使い分け)
  • 除外: 制限大会 (西武撃 Rising / LIMIT BREAK / RAISE / ビギナー杯 等), 下位クラス (B〜E クラス, スマパカジュアル 等), 身内大会 (合宿 / 帝国 / 内輪 等)。 これらは出場資格が偏っているか、上位帯のシード予想が成立しないため評価対象から落とす。
  • 件数: 統計的に安定した τ 値を得るのに十分な数 (数十件規模)

1.2 Rolling evaluation (リーク防止)

評価で最も重要なのは「未来の情報を使った予測になっていないか」。 SPSP では大会を時系列順に処理する:

  1. 大会 T の開始日時を取得
  2. T 開始より前のデータだけで全プレイヤーの SPSP レートを再計算
  3. そのレートから T 参加者の予測順位を生成
  4. T の実際の結果と比較して精度を測る
  5. 次の大会 T+1 に進む

この方式で「学習データに test 大会が混ざる」ことを構造的に排除している。 本番運用と同じ条件で精度を測れる。

1.3 評価指標

順位予測のずれを 2 通りで測る:

  • Kendall τ: 「予測順位」と「実際の最終順位」の順位相関。 1 = 完全一致、0 = ランダム、-1 = 完全逆順。値が大きいほど良い。
  • |SPR| mean: SPR = W2W(seed) − W2W(place)。 W2W (Wins-to-Win) は「ダブルイリミでその順位に到達するために必要な勝ち数」のこと (例: 1 位 = 全勝、最下位 = 0 勝)。SPR の絶対値はシード位置と最終順位を 勝ち数換算で比べた絶対誤差。 値が 小さい ほど良い。 W2W の厳密な定義は 理論編・数式 §3.1 を参照。

さらに「上位何位までを評価対象にするか」を scope K で分けて見る: K = 8, 16, 32, 64, 128, 256, 512, 1024。 Top 8 だけ見ると最上位帯の精度、K=1024 だと全体の精度になる。

なぜ scope を分けるか: 上位帯と中下位帯では「重要な情報」が違う。 Top 8 は「強い人同士の試合の質」、Top 256 は「どの帯にいるか」。 全体平均だけ見ると、両方の弱点が見えなくなる。

2. 直対評価モデル選定 (OpenSkill BT → Glicko2)

V4 では直対評価モデルを OpenSkill BradleyTerryFull から Glicko2 に変更 した。 両モデルとも Elo を確率的に拡張したベイズ系レーティングだが、Glicko2 は 更新速度 (= 覚醒の追従性) で有意に勝る。ここで採用経緯をデータで示す。

2.1 Glicko2 を採用した理由

  • 覚醒の追従性: Glicko2 は OpenSkill BT より RD (不確実性) の縮みが緩やかで、 ベテランでも連続で番狂わせを起こせばレートが目に見えて動く。 旧版で σ floor によって人為的に補っていた「上方修正の余地」が、Glicko2 では volatility と RD の 組み合わせで 自然に 出る。
  • パラメータ削減: 旧版は (σ floor, σ inactivity target, sigmoid params) と ハイパラ調整が多かったが、Glicko2 ベースでは σ floor を 完全に除去 できた。 RD inflation の sigmoid だけ残る (= 不参加期間の追従用)。
  • 収束の安定性: warmup を入れない pure な ensemble pfilter (= LV-gated update) で評価しても、 Glicko2 は OpenSkill BT より rank stability が高い。

2.2 V4 採用の決定的根拠

篝火#14〜篝火#15 (N=37) で V4 (= Glicko2 + LV-gated + ens-pure + LV3wk + LV4 nent>32) と v1/v2 prod を比較:

構成PairAcc ↑|SPR| ↓備考
v1 (旧版 = OpenSkill BT + σ floor)0.86251.0261v1 基準
v2 prod (info TJPR + M-tour gating)0.87660.9750v2 base
V4 (Glicko2 + ens-pure + LV3wk + LV4 nent>32)0.87990.9642採用

V4 は PairAcc・|SPR| ともに v1 / v2 prod を上回る。Top 8 帯の改善も大きい (= 覚醒勢の追従が effective)。これにより V4 を本番採用とした。

Glicko2 RD inflation の併用: Glicko2 単体だと長期離脱者の RD が小さいままで、復帰戦の追従が弱い。 V4 では sigmoid ベースで 30 日 grace → 540 日で中央 → 漸近 RD=128 という inflation を加えている。 全 scope の Kendall τ が改善することを確認済み。

3.2 何が分かるか

  • Top 8 では直対評価単体が強い (+0.025 vs ensemble)。最上位帯は試合の質で決まるため、順位ポイントを混ぜると逆に劣化する
  • Top 16〜1024 ではバランス側がベスト。順位 : 直対 ≈ 0.4 : 0.6 か 0.5 : 0.5 が天井近く
  • 全 K で安定して良い 0.5 : 0.5 を公式採用
  • 0.0 : 1.0 (直対のみ) と 0.5 : 0.5 の差は K=128 で +0.0007 程度。順位評価が混ざることで分解能を底上げしている
「単純平均」の理由: 0.4 : 0.6 のほうがわずかに上だが、差はノイズレベル。 シンプルさを優先し、調整パラメータを減らすため 0.5 : 0.5 (= rank avg) を採用した。

4.1 何が分かるか

  • SPSP V4 は v1 (旧版) を PairAcc +0.017、|SPR| −0.062 改善。 Glicko2 + LV-gated + ens-pure pfilter の合わせ技が効いている。
  • SPSP V4 は JJPR v3 を Kendall τ で +0.07、|SPR| で −0.17 改善。37 大会で再現性のある差。
  • 直対系単体 (Glicko2 / OpenSkill BT) は PairAcc / τ で SPSP V4 にやや劣る。 順位評価の 5 層カスケードを ensemble で組み合わせることで |SPR| をさらに 0.030 程度改善。
  • V4 設定では Glicko2 BT + LV-gated update + ens-pure pfilter + LV3wk + LV4 nent>32 + rank avg ensemble の組み合わせで上位帯の精度を最大化している。
